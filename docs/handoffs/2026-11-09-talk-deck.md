### The app and its features, which are the deck's subject matter

Matter Cockpit is a legal-matter demo app built live with Claude Code. It uses synthetic matters only, plus public court orders. Read `CLAUDE.md` for the stack and rules, and `docs/plans/` for each feature's product contract.

- **Deadline Radar:** every deadline across matters, with a "This week" band.
- **Cockpit:** one matter in depth, with tabs. "Overview", "Scheduling order", and "Compare drafts" are feature tabs registered through `src/features/`.
- **Client Portal:** the client-facing view. It hides internal reasoning and evidence, and it hides public-record matters.
- **Ramble intake:** speak a matter by voice and the model builds a schema-valid matter. Supporting controls are the "Embellish" button and the "Show what I said" toggle. Plan: `docs/plans/2026-11-08-1555-feat-matter-cockpit-cle-demo-plan.md`.
- **Trust but Verify:** a drawer that shows deadline math step by step, with the rule's own words. Examples are FRCP 6(a)/6(d) and Minnesota Gen. R. Prac. 115.03. A toggle switches service methods.
- **Scheduling-order upload:**
  - The model extracts court-set dates. The server checks every quote against the order's page before saving.
  - Code, not the model, computes every rule-derived deadline.
  - It can export a `.ics` calendar file.
  - Plan: `docs/plans/2026-11-08-1937-feat-scheduling-order-upload-plan.md`.
- **Public-record matters:** three real D. Minn. scheduling orders are bundled (`THIRD-PARTY.md` lists their captions and sources). Each opens as a matter marked "Public record". Plan: `docs/plans/2026-11-09-0531-feat-public-order-matters-plan.md`.
- **Draft Compare** (PRs #4 and #5): any two drafts in Word, PDF, text, Markdown, .doc, .rtf, .odt, or HTML.
  - **Redline:** a Word-faithful Track Changes view with linked moves, built by the Docxodus engine (MIT).
  - **FOLIO tags:** legal concepts tagged from the open FOLIO ontology (CC BY 4.0).
  - **Parties:** detection with FOLIO actor labels. The lawyer confirms which party they represent.
  - **Advice:** streamed Harms/Neutral/Helps advice per change, every quote verified. A memo groups the changes.
  - **Downloads:** a redline .docx with Word margin comments, and a counter-draft .docx whose edits are the lawyer's own tracked changes.
  - **Samples:** six fictional pairs, one per practice family: transactional, litigation, regulatory, legislative, advisory, and bankruptcy.
  - Plan: `docs/plans/2026-11-09-0816-feat-draft-compare-plan.md`.
- **Themes:** Law Review, Mission Control, and Boutique Firm. Design is token edits in `src/theme/tokens.css`. The run of show ends with "make the accent Vikings purple".
- **`/cook`** (`.claude/skills/cook/`): turns a crowd idea into a scoped, built, and tested feature live. Six pre-built fallback ideas live on local `fallback/*` branches. `docs/rehearsal/fallback-timings.md` lists each idea, its build time, and its tip.

**How it was built.** Damien gave direction, mostly by voice and Remote Control. A Claude orchestrator planned and reviewed. Codex workers wrote the code in parallel worktrees, using the Compound Engineering loop: brainstorm → plan → work → review → compound.

## Recommended approach (the writer's own call, not Damien's; check the bolded decisions with him)

### Hosting without Tailscale

**Recommended host:** a claude.ai Artifact. Run the Artifact tool's `quickstart` with intent `slides` first; it may offer a Slides type built for click-through decks. Otherwise, hand-build one self-contained HTML page after loading the `artifact-design` skill.

Why an Artifact fits:

- It is private by default.
- It opens in any browser where Damien is signed in to claude.ai.
- It needs no Tailscale and no local server.

**Alternative:** Damien's own site, damienriehl.com, for example its sketches directory. That host is public. **Damien's choice:** Artifact versus his site. Recommend the Artifact and build it. The page must still work if he moves it.

**Never use Proof** (his standing rule).

### Toggling between the deck, Claude Code, and the app

**The app is local.** The web app runs on the presenter's machine at `http://127.0.0.1:8982`, started per runbook step 5 with the converter env var. If the presentation browser runs on another machine, use the `tailscale serve` host that `MATTER_COCKPIT_ALLOWED_HOSTS` names. Only the deck must avoid Tailscale.

**Persistent controls.** Give the deck a small, unobtrusive control bar or keyboard shortcuts:

- `A` opens the app.
- `C` opens Claude Code.
- `←`/`→` move between slides.

**Named tabs.** Use links with named targets, such as `target="cockpit-app"` and `target="claude-code"`, so repeated clicks reuse one tab instead of spawning new ones.

**Constraints:**

- **Popup restrictions:** artifacts render in a sandboxed iframe on claude.ai, and named-target links and popups may be restricted there. **Test this in a real browser.**
- **No iframes:** never iframe the app into the deck. Mixed content and the sandbox both block it.
- **Configurable URLs:** make the app and Claude Code URLs configurable in one place. Accept a `?app=` query parameter, or an editable field that remembers its value in localStorage.

**Most robust fallback:** document it on a "presenter setup" note. Use one browser window with three tabs pinned in order: deck, Claude Code (the claude.ai/code session or the terminal), and app. Switch with Ctrl+1, Ctrl+2, and Ctrl+3, or Ctrl+Tab.

**Claude Code URL:** the Claude Code "session" is either a terminal or a claude.ai/code Remote Control session URL. **Ask Damien which one he will present from, and its URL.**

**Fullscreen:** support it with the `F` key and the Fullscreen API. Keep slide state in the URL hash (`#7`), so a reload or a jump back lands on the same slide.
